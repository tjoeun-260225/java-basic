Servlet
 - 자바로 HTTP 요청을 처리하는 방식
 - URL 하나마다 클래스 하나, 설정 파일을 한 줄 씩 추가
 예를 들어 https://www.naver.com/login 접속
 소비자는 로그인 버튼을 클릭해서 위 경로의 주소로 접속
 소비자는 아이디 비밀번호를 작성하고 작성한 데이터를 네이버
 서버로 전달하여 로그인 요청

 소비자 로그인 버튼을 클릭해서 로그인 페이지 이동
 get /login      백엔드 코더는 작성
 소비자 로그인 페이지에서 아이디 비밀번호를 작성 후 로그인 요청
 post /api/login 백엔더 코더를 개발자는 작성
 소비자는 개발자가 get post 로 어떤 url로 처리를 하는지 알 수 없다.

 HTTP
 - 브라우저와 서버가 대화하는 규칙
 - 브라우저가 서버한테 "우리 고객님이 이걸 원한대" 요청(Request)하면
 - 서버가 여기에 응답(Response) 하는 구조
   응답을 할 때는 조건에 부합하는지 확인 후 응답(긍정/부정/이외) 반환

   소비자가 인터넷 주소창에
   네이버 검색
                             소비자가
                             우리 사이트에
                             접속하겠대!!!    아그래?
   네이버 주소창(브라우저) ─   Request    → 서버
                                             서버
   네이버 주소창(브라우저)  ←  Response   ─  1. 로봇이 접근했는지
    서버에서 전달해주는        옆 3가지      2. 한국 이외 ip 접속해서
    html 화면 반환             문제가           접근했는지
                               없을경우      3. 디도스 공격할 문제가 발생하는 곳인지
                               login.html       와 같은 기타 상황 확인
                               과 같은 화면 반환
    위의 경우는 대부분 Get 으로 요청 처리

    GET - 데이터를 가져오거나 특정 페이지를 보여줄 때 사용
    "나 이거 보여줘" 요청
    조회할 때 사용

    https://search.naver.com/search?query=자바&page=1
    네이버 검색 주소 에서   검색   쿼리스트링
    ? = 경로 끝 / 소비자가 선택한 데이터 시작 신호
    ? 앞은 어느 브라우저 주소로 갈지
    ? 뒤는 뭘 들고 갈지 결정(=소비자가 선택한 상품 페이지 등...)
    & = 데이터 여러 개를 구분하는 구분자
    데이터(파라미터)가 여러 개 일 때 &로 붙인다.

    https://search.naver.com/search?query=자바&page=1&size=10
    ?
    query=자바   소비자가 인터넷주소창에 자바를 검색한 상태
    page =1      1페이지에서 자바 검색을 확인하고 있는 상태
    size =10     1페이지에 10개의 데이터 조회

    쿼리 페이지 사이즈는 어떤 개념으로 명칭이 작성되고 숫자
    → 개발자가 지정한 주소 체계 명칭으로
      쿼리라는 변수에 자바를 담고 페이지라는 변수공간에 숫자를 담고
      사이즈라는 변수에 개수를 담아서 소비자에게
      위 정보가 들어간 html or jsp 페이지를 반환

    =  키=값 쌍을 연결하는 구조
    &  그리고 와 같이 데이터를 구분하는 기호

    URL 데이터가 보이기도 하고 보이지 않기도 한다.
    Header Body 체계에 따라 달라진다.
    URL 길이 제한이 있다.
    브라우저마다 다르지만 보통 2000자 내외
    민감한 데이터는 ? 형태로 넘기지 않고, body 형태로 넘긴다.

    POST
    - 데이터를 서버에 전달할 때
    - 나이거 처리해줘 요청 생성 로그인 파일 업로드 등 사용
    - 데이터를 URL이 아닌 요청 본문에 담아서 보냄
    - 로그인 회원가입과 같이 소비자가 선택하거나 기입한 데이터를
      서버에 전달하고 결과를 요청할 때 사용

  특징
  - Tomcat 같은 WAS(웹 애플리케이션 서버) 위에서만 동작
  - JSP도 결국 컴파일되면 Servlet 변환됨 - JSP Servlet 편의 문법
    Spring MVC도 내부적으로는 DispatcherServlet 이라는 Servlet 하나가
    모든 요청을 받아서 컨트롤러로 분배

JDBC - 자바에서 DB에 SQL을 직접 날리는 방법
Java DataBase Connectivity
자바와 DB를 연결하는 표준 API

MyBatis JPA 도 내부적으로 전부 JDBC 위에서 동작
기본 흐름
1. DB에 연결
2. SQL 준비(PreparedStatement)
3. SQL 실행
4. 결과 읽기 (ResultSet)
5. 연결 닫기(close)
